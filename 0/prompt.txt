Confirmed. Here's the bug:

The landing page (/) never redirects anywhere after login, and it doesn't check auth state at all.

- Your "Sign in" / "Get started" buttons both just link to /auth/login with no returnTo param (src/app/page.tsx:16,28).
- The Auth0 SDK (@auth0/nextjs-auth0 v4) processes /auth/login → Auth0 Universal Login → /auth/callback via the middleware in src/proxy.ts, and when no returnTo was specified, it lands you back on / by default.
- src/app/page.tsx is a plain static landing page — it never calls auth0.getSession(), so it renders identically whether you're logged in or not. You end up back on http://localhost:3000/ looking at the exact same "Sign in" button, which looks like sign-in silently did nothing.
- The actual authenticated app lives under the (app) route group (/today, /pantry, etc.), guarded by src/app/(app)/layout.tsx, which does call requireUser() — but nothing sends you there after login.

So it's not failing — you are signed in, you're just stranded on a landing page that doesn't know or care that you're signed in.

Fix: point the sign-in links at /today as the return destination, e.g.:

<a href="/auth/login?returnTo=/today" className={buttonClass("primary", "lg")}>Get started</a>

(@auth0/nextjs-auth0 v4's /auth/login route accepts a returnTo query param.) Optionally, also make page.tsx check auth0.getSession() and show a "Go to app" link / redirect when already signed in, so a signed-in user hitting / isn't stuck looking at the marketing page either.
