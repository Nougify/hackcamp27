## 2. Server vision logic: `label.ts` and `date.ts`

### `src/server/vision/label.ts` — `buildLabelResponse(x: LabelExtraction, model, gtin)`
Pure function. Treats the already-Zod-validated `LabelExtraction` as still untrustworthy and re-derives everything into a `flaggedFields: Set&lt;Flag&gt;`:
- `clean()` (line 48) nulls out and flags any negative nutrient.
- kJ-only labels: regex `KJ_IN_NOTES` pulls a kJ figure out of Gemini's free-text `notes` and converts (`÷4.184`), flagging `energyKcal` since it's derived, not printed (lines 68-75).
- `macrosConsistent()` (line 30) is an exported pure cross-check: `4p+4c+9f` vs `kcal`, tolerance `max(20%, 5kcal)` absolute floor for near-zero labels (`MIN_KCAL_TOLERANCE`); on failure flags all four macro fields.
- Serving size sanity range 1–1000 (line 82); if present but out of range, flags `servingSize`.
- If `basis === 'unknown'`, every non-null nutrient gets flagged (can't trust numbers with no known basis) (lines 89-92).
- Package quantity validated `&gt;0` before being mapped through `PACKAGE_UNITS` (line 19) into the app's `DisplayUnit`.
- GTIN: `draftGtin()` (line 36) only trusts a barcode if it round-trips through `normalizeBarcode()` (`src/lib/gtin.ts`), preferring the client-supplied `gtin` form field over Gemini's OCR'd `barcode_digits_if_visible`.
- **Allergens are never taken from Gemini at all** — `allergenTags: []` is hardcoded (line 118); the user must tick them manually in `ProductForm.tsx`. This is the project's strongest "don't trust the model" move for this endpoint.
- Final return is `{ isFoodProduct, draft: ProductDraft, flaggedFields, macrosConsistent, confidence, notes, model }` — exactly `LabelExtractionResponse` from `src/contracts/api.ts:38-46`.

### `src/server/vision/date.ts` — the CFIA cross-check
- `parseCfia(rawText)` (line 34) runs the CFIA month-code regex (`CFIA`, line 22) against Gemini's `raw_text`, first stripping the bilingual "BB/MA" marker (line 24) so it isn't misread as the month May. Regex is deliberately bounded (`(?!\d)`, `(?![A-Z])`) so adjacent digits/letters can't be swallowed into a false match (e.g. "MA 2026" vs "MAY" vs "NORTH 12").
- `regexCrossCheck(x)` (line 44) independently re-derives month/day/year from the raw OCR text and compares against what Gemini's structured fields claim (handling `ambiguous_order` swap), returning `'agree' | 'disagree' | 'no_match'` — this is surfaced to the UI as a trust signal, not used to silently override Gemini.
- `assembleDate(x, today)` (line 81) is the actual "don't trust the model" gate on dates:
  - `packaged_on` or missing month/day → `suggestedDate: null` (never offered as an expiry).
  - Missing year → `nextOccurrence()` picks the next calendar date ≥ today (not an arbitrary year).
  - Candidate dates are clamped to `[today-1y, today+5y]` (`earliest`/`latest`, lines 95-96) — directly implements SPEC F4's "reject dates more than 5 years ahead or more than 1 year past."
  - Ambiguous day/month order produces up to 2 deduped candidates and sets `needsUserChoice: true` so the *user* disambiguates, never the server.
